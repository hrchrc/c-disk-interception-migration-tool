# C盘拦迁器 (C Drive Relocator) v0.02

监控·拦截·迁移·修复·开发环境配置 全方位守护 C 盘。防止软件在 C 盘创建数据，自动迁移到其他盘符并通过符号链接保持兼容。

## 启动

```bash
pip install -r requirements.txt
python src/main.py
```

**必须以管理员身份运行**（创建符号链接、终止进程、写注册表环境变量需要管理员权限）。启动后自动构建 MFT 索引（数秒）→ 加载 winget DB → 扫描 C 盘 6 个目录 → 启动目录监控。

## 核心功能

### 1. 毫秒级安装拦截
- **ReadDirectoryChangesW** 内核级目录监控，目录创建瞬间触发 kill
- 三重识别策略：%TEMP% 路径 / 安装目标目录 / 14 个安装器关键词 + 最近 30 秒启动
- 40+ 系统关键进程白名单 + Windows 路径过滤，避免误杀
- 三级删除策略（`rd /s /q` → `shutil.rmtree` → 重命名）清理残留文件

### 2. 待迁移区（C 盘大目录扫描）
扫描 C 盘 6 个监控目录下的一级子目录，列出路径、位置、大小、目录名、说明。

**核心能力**：
- **MFT 加速扫描**：内置 Rust 引擎独立进程构建全盘 MFT 索引（紧凑数组存储 + 按需分页，内存占用低），目录大小计算零磁盘 I/O，任意大小目录 < 0.1 秒；Rust 路径失败自动回退 Cython 批量解析，再失败回退 os.walk
- **13 层软件识别 + 智能兜底 + AI 兜底**：组合匹配 → winget DB（19421 包，含中英 desc）→ 关键字 → updater 后缀 → 通用词 → 反向域名 → 注册表+WMI → 特征文件 → App Paths+lnk → PE 版本 → lnk+文件标识 → 厂商容器 → 智能兜底 → AI 兜底（7 平台可选）
- **文件名快速搜索**：顶部搜索框基于 MFT 索引按文件名搜索整个 C 盘，毫秒级返回，支持 `*`/`?` 通配符
- **异步描述补全**：DescFillThread 串行处理 + 单条 5 秒超时，避免并行锁争抢
- **说明列 4 种前缀**：[~] 异步补全中 / [?] 置信度低 / [系统] 系统文件整行橙色 / [已配置] 开发环境迁移区已配置
- **多选批量迁移**：Ctrl/Shift 多选，右键菜单支持迁移到默认盘/指定位置，4 个迁移入口全部 QThread 异步执行不卡 UI
- **系统文件保护**：20 种系统路径前缀 + 7 个关键词识别，整行橙色标记，单选弹红色警告，批量含系统文件直接拒绝
- **双击编辑说明**：双击说明列进入编辑模式，手动修改软件描述
- **搜索过滤**：按路径/目录名/说明关键词实时过滤表格
- **复制进度实时输出**：迁移时复制进度实时输出到状态栏（左下角）和监控日志
- **自动同步**：迁移成功后自动从待迁移表删除，添加到已迁移表，无需手动刷新
- **断点续传**：迁移过程分 6 步记录 stage，意外中断后下次启动自动从断点续传

### 3. 已迁移区（符号链接管理）
显示所有已迁移记录，7 列：C 盘路径 / 目标盘 / 大小 / 状态 / 链接目标 / 说明 / 迁移时间。

**核心能力**：
- **4 种链接状态实时显示**：
  - **正常**（绿色）：链接有效，目标盘数据存在
  - **断链**（红色）：软件把符号链接覆盖成真实目录（软件更新时常发生），可修复
  - **丢失**（橙色）：C 盘路径不存在了（可能被手动删除），可重建
  - **目标丢失**（深红）：目标盘数据没了（U盘/移动硬盘已拔出或数据被误删），需重新迁移
- **链接目标列颜色提示**：绿色=目标存在正常 / 红色=目标异常 / 灰色=该路径不是符号链接（可能是真实目录）
- **后台自动修复**：每 60 秒自动检测所有已迁移目录，发现链接被软件覆盖就把 C 盘新数据用复制引擎合并到目标盘并重建链接，无需手动处理
- **批量修复/还原/重建/删除**：右键菜单支持多选批量操作
  - 修复链接：把 C 盘新数据合并到目标盘后重建符号链接（断链时用）
  - 还原选中：数据复制回 C 盘，删除符号链接，删除迁移记录
  - 重建链接：不合并数据，直接在 C 盘重建符号链接
  - 删除链接：只删 C 盘符号链接，保留目标盘数据
  - 删除记录：从已迁移列表移除该条目（不删数据）
- **复制进度实时输出**：还原时复制进度实时输出到状态栏和监控日志
- **搜索过滤**：按路径/说明/状态关键词实时过滤
- **双击打开目标盘目录**：双击行直接在资源管理器打开目标盘目录
- **还原后联动**：还原成功后自动从已迁移表删除，添加到待迁移表，并撤销对应开发工具的环境变量配置

### 4. 开发环境迁移
30+ 开发工具的环境变量/配置文件/数据一体化迁移：

| 类别 | 工具 |
|------|------|
| Node.js | npm、yarn、pnpm |
| Python | pip、conda |
| Rust | cargo、rustup |
| Go | GOPATH、GOCACHE、GOMODCACHE |
| .NET | dotnet tools、nuget |
| Java | gradle、maven（含 settings.xml 自动配置） |
| Android | Android SDK、NDK |
| C++ | conan、vcpkg |
| 其他 | Ruby / Julia / PHP / Dart / R / Haskell / Scala / Swift / Bazel / VS Code 扩展 |
| 仅指引 | Docker / WSL / Visual Studio |

**核心能力**：
- **环境变量自动配置**：写入注册表 HKCU\Environment + 广播 WM_SETTINGCHANGE，新终端立即生效
- **配置文件自动修改**：Maven settings.xml、Bazel .bazelrc 等自动备份原文件后修改，支持还原
- **数据迁移可选**：配置环境变量时可选是否同时用复制引擎搬 C 盘数据到目标盘，C 盘原位置变符号链接（对工具透明）
- **默认勾选规则**：已安装且未配置过的工具自动勾选，未安装/已配置过的工具不勾选（可手动改）
- **双击改路径**：双击「建议新路径」列可弹浏览对话框自定义目标位置
- **一键补配**：扫描所有「数据已迁移但环境变量未配置」的工具，一键批量补配环境变量（适用于先在待迁移区迁移了数据，但没配环境变量的场景）
- **状态可视化**：6 种状态实时显示工具的安装/配置/迁移情况，单击「未安装」单元格可弹出官网下载菜单
- **路径异常检测**：环境变量指向无效路径时标记「⚠ 路径异常」，建议还原后重新配置
- **父目录符号链接识别**：工具路径的父目录（如 C:\Android）是符号链接时，还原会识别并还原整个父目录

**状态列**：未安装 / ✓ 已就绪 / ✓ 已配置到 X:盘 / ✓ 已迁移到 X:盘 / ⚠ 已配置（数据未迁移）/ ⚠ 路径异常

**还原流程**（全自动执行）：
1. 撤销环境变量（删除注册表项 + 执行 unconfig 命令 + 还原 Maven/Bazel 配置文件）
2. 复制引擎数据回 C 盘 → 验证文件数完整 → 删除 C 盘符号链接 → 删除 D 盘冗余数据
3. 清理配置记录（从 dev_env_configured 移除）
4. 自动刷新三个区（开发环境迁移区 + 已迁移区 + 待迁移区）

数据完整性验证失败会中止还原，不会丢数据。还原前自动取消并等待相关扫描线程完成，避免目录访问竞争。

### 5. 配置快照系统
仿 GitHub commit 的开发环境配置快照，可保存任意时刻的所有环境变量值和配置记录，随时回滚到历史状态。

**核心能力**：
- **快照内容完整**：保存所有相关环境变量的当前值（env_values）+ 开发环境配置记录（dev_env_configured 完整副本）+ 原始目录结构（original_dirs，便于查看配置前的目录状态）
- **独立文件存储**：每个快照独立保存为 `dev_env_snapshots/YYYYMMDD_HHMMSS.json`，方便单独查看/恢复/删除
- **500 个上限**：最多保留 500 个快照，超出自动删除最旧的（首个原始快照永久保留）
- **首个原始快照（🛡️ 标记）**：程序首次在本机运行时自动创建，文件名带 `_initial` 后缀，含唯一 UUID，是"还原到初始状态"的最终底线
  - **双重保护**：设为"隐藏受保护的操作系统文件"属性（资源管理器默认不显示）+ 隐藏的完整备份文件 `.original_snapshot.bak`
  - **自动恢复**：即使用户删了首个快照，下次启动时会从隐藏备份完整恢复（内容/UUID/时间戳全部不变，不是重新生成）
  - **身份唯一性**：手动创建的快照永远不带 `_initial` 后缀和 UUID，无法冒充原始首个
  - **永不被自动清理**：超出 500 上限时只删非首个快照
- **快照标记**：⭐ 星标 + 🏷 自定义标签（独立存储于 snapshot_marks.json，不修改快照本身），"只看星标"按钮快速筛选
- **恢复可撤销**：恢复快照前自动创建当前状态快照（带"恢复前自动备份"标记），随时可恢复到恢复前的状态
- **多种操作**：恢复此快照 / 还原到默认状态（清空所有配置）/ 查看详情 / 加星标标签 / 删除
- **恢复后联动**：环境变量已恢复 → 开发环境迁移区表格自动刷新 → 已迁移区和待迁移区联动刷新

### 7. MFT 加速扫描
内置 Rust 引擎（rust-migrate-engine.exe）独立进程构建全盘 MFT 索引：
- **构建**：读卷 → FSCTL 卷参数 → 定位 $MFT → 批量读取（无缓冲 I/O）→ USA fixup + 属性解析 → 索引构建（紧凑数组）→ 拓扑预计算目录大小，全流程 Rust 完成，数秒出结果
- **加载**：Python `array.frombytes` 直载，查询代码零改动；名字池按需分页、内存占用低（常态 ~100MB 内）
- **降级链**：Rust 路径任何一步失败 → 自动回退 Cython 批量解析 → 再失败回退 os.walk，全程日志记录原因
- **查询**：目录大小计算零磁盘 I/O，任意大小目录 < 0.1 秒；文件名搜索毫秒级返回

## 技术栈

- **Python 3.13** + **PySide6** (GUI)
- **psutil** (进程监控) + **pywin32** (PE/WMI/注册表)
- **ctypes** (ReadDirectoryChangesW 内核级目录监控)
- **Rust 引擎**（rust-migrate-engine.exe，位于 bin/）：MFT 索引构建 + 迁移复制引擎（BLAKE3 校验/断点续传）
- **Cython** (MFT 解析兜底路径)
- **i18n 语言包**（i18n/ 目录，界面多语言支持，默认中文）

## 注意事项

- 必须以**管理员权限**运行
- 迁移前请先关闭对应软件，避免文件被占用
- 开发环境迁移后需**重新打开终端/编辑器**才能让环境变量生效
- 系统文件（[系统] 标记的目录）请勿迁移，可能导致系统异常
- 建议使用固定盘作为迁移目标，移动设备拔出后链接会失效
- API Key 独立存储在 ai_keys.json，清空缓存不会丢失
